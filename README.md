# 宝马车控 — REAREye背屏组件
为Xiaomi带有背屏的设备制作的 BMW 车控卡片。
可查看车辆剩余电量、续航，使用空调、闪灯、鸣笛入口，并自定义汽车名称、型号和图片。

# 功能

# 车辆信息
- 显示汽车名称、型号、车辆图片、剩余电量、续航和数据获取时间。
- 自定义名称、型号及字号；型号可以留空。
- 从相册导入车图，调整图片大小和上下、左右位置。
- 保留默认车图，关闭自定义图片即可恢复。
- 操作提示约 4 秒后隐藏；界面不显示“直连”标识。

# 车况更新

按手机本地时间，在 **08:00 至次日 01:00 每个整点**尝试读取车况，**02:00—07:59 暂停背屏脚本的定时查询**。
打开卡片显示已有缓存，不立即查询宝马云端。更新失败保留上次数据及获取时间；深度休眠时，整点更新可能延后或跳过。

# 控车入口

| 入口 | 实际行为 |
| --- | --- |
| 空调 | 核对授权和车辆后，单次提交开启请求 |
| 闪灯 | 单次提交闪灯请求 |
| 鸣笛 | 单次提交鸣笛请求 |
| 锁车、解锁 | 跳转前屏 My BMW，由官方流程操作 |
| 定位、打开 App | 打开前屏官方入口 |
| 更新授权 | 同步官方 App 本机已有授权，不发送控车指令 |

“请求已受理”表示服务端接收了请求，最终执行情况以车辆或 My BMW 显示为准。超时、断网或结果未知时，不自动重发。
控车时遇到授权过期或被拒绝，会尝试打开前屏 My BMW；处理授权后，需要手动重新发起操作。

云端包包含 `widget_info.json` 和 `scripts/`；本地包把配套脚本放在根目录，并使用固定的本地项目路由。两种包应按各自用途安装。

# 使用条件

- Xiaomi，REAREye 已正确启用并获得所需 Root 权限。
- REAREye 支持脚本项目和普通卡片模板；云端安装还需支持组件自带脚本及安装后初始化。
- 中国大陆 My BMW 已登录，首页能够正常显示所需车辆。
- 保留可用的 Termux 与 Python。本包不包含完整 Python 环境。

当前适配参照：REAREye **2.0.0-5ca03c1-r251-canary**、My BMW **6.9.0（54521）**。其他版本、系统和车型需要另行核对。车辆支持哪些远程服务，由车辆配置和官方账号权限决定；可以自定义车型外观，不代表所有 BMW 车型都已完成控车实测。

# 安装与使用
# 本地安装

1. 下载 `BMW_i3_Cloud_AllInOne.zip`，保持原文件名。下载器若添加了 `(1)` 等后缀，请先改回原名。
2. 在 REAREye 的“脚本项目”入口导入该 ZIP，项目名称保持 `BMW_i3_Cloud_AllInOne`。
3. 在“背屏模板／组件”入口导入同一份 ZIP，创建或应用一张 **普通 BMW 卡片**。
4. 在 My BMW 确认当前登录和车辆正确，再按下文绑定车辆。

只导入模板不会同时完成本地脚本安装。项目名改变后，卡片可能找不到脚本。

# 云端安装

1. 本版发布并被商店收录后，在 REAREye 云端下载 BMW 组件。
2. 按宿主提示安装或应用卡片，允许需要的 Root 操作，等待初始化。
3. 云端组件会同时提供配套脚本；首次使用仍需确认官方登录和车辆绑定。
4. 需要查看组件脚本时，项目 ID 为 `component:bmw_i3_cloud`。

# 绑定当前车辆

在对应脚本项目的调试页填写：

```text
Provider ID：setup_new
参数：vin=你的17位车架号
```
从 My BMW 车辆详情复制车架号，只在自己手机上填写，无需上传。官方缓存能够确认唯一车辆时，参数也可留空。

等待后台处理后，分别检查：

- `status`：应显示“已重新绑定当前车辆”。
- `hidden_status`：查看最近检查是否已绑定隐藏官方组件。

车辆绑定和隐藏组件绑定是两件事。绑定成功不等于控车已执行，也不等于授权会永久自动续期。

首次绑定后，电量和续航暂时显示 `--` 时，可等待下一个允许更新的整点。需要立即查询车况，可明确运行 `cloud_check`；它只查询车况，不控车。

# 自定义名称、型号和图片

进入 **REAREye → 卡片管理器 → 普通 → BMW 卡片 → 滑杆／调节图标 → 模板配置**。

1. 修改“汽车名称”和“型号／配置”。
2. 在“汽车图片”中选择自己的图片，确认“使用自定义车图”开启。
3. 按需要调整大小、位置和字号，然后保存。
4. 重新进入背屏卡片查看；本地外观读取的兜底轮询间隔为 **10 秒**。

建议使用横向透明 PNG。普通 JPG 会保留照片背景；组件不自动抠图，图片按原比例显示。图片加载失败时保留默认车图。

这些设置只改变外观，不改变实际控车车辆。真正更换账号或车辆时，需要在 My BMW 确认目标车辆，并执行显式重新绑定。

# 授权与隐藏官方组件

登录和新授权由 My BMW 管理，背屏同步本机已有授权。此前观察到令牌声明时长约 **55 分钟**，实际有效性以官方接口为准；同步缓存不会重新计算到期时间。

初始化会检查或创建一个不显示界面的官方续航组件实例，复用已有专用绑定，不占普通桌面或负一屏面积。其更新仍受官方逻辑、后台限制、系统调度和联网状态影响。

**隐藏实例已绑定，不代表长期自动续期已保证。** 授权失效时，打开 My BMW 完成登录或刷新，再在背屏更新授权。原控车指令不会自动补发。

背屏定时查询与官方 App 后台任务分别运行。夜间暂停的是本组件的定时查询，不代表官方 App 在该时间段一定不会联网。

# 常用检查入口

在对应的本地或云端组件脚本项目中运行；除特别说明外，参数留空。

| Provider ID | 用途 |
| --- | --- |
| `status` / `link` | 最近处理结果、版号和阶段 |
| `appearance_status` | 本地外观读取状态、来源编号、图片是否已选择 |
| `appearance_sources` | 在手机上列出可选外观编号、名称与型号 |
| `auth_info` | 已有令牌的签发、到期和缓存同步时间 |
| `runtime` | 部署／检查后台运行库及启动已有计划，不重新绑定 |
| `schedule` | 整点更新计划和最近车况状态 |
| `cloud_check` | 手动查询一次车况，不控车 |
| `hidden_status` | 最近一次隐藏宿主检查结果 |
| `hidden_inspect` | 排队检查隐藏宿主，稍后再看 `hidden_status` |
| `hidden_enable` | 检查或创建隐藏实例，复用已有绑定 |
| `hidden_remove` | 移除本组件的专用隐藏实例 |
| `updates_off` / `updates_on` | 暂停／恢复背屏整点查询 |
| `bootstrap` / `bootstrap_status` | 云端初始化与阶段检查 |
| `setup_new` | 显式绑定当前账号与车辆，可传入 `vin` |

# 常见问题

**卡片提示脚本未连接。**

确认脚本和模板都已安装，本地项目名为 `BMW_i3_Cloud_AllInOne`。云端包与本地包使用各自配套的路由。

**找不到编辑车型和图片的入口。**

进入“普通”卡片页。当前“应用”页的 My BMW 应用卡片没有这个模板配置入口。再确认当前普通卡片使用的是包含 `var_config.xml` 的新版 BMW 模板。

**保存名称后仍没有变化。**

先确认这次同时覆盖了脚本和模板，再运行 `appearance_status`。有多份历史外观时，用 `appearance_sources` 核对并固定来源。详细排查及只读检查脚本用法见[外观说明](自定义外观使用说明.md)。

**名称变了，图片没有变化。**

在模板配置中明确选择图片、开启自定义图片并保存。`appearance_status` 显示“未选择”时，没有可供读取的图片记录。图片选择和名称输入是不同设置。

**授权同步时间更新了，仍提示过期。**

同步时间表示重新读取了缓存。先在 My BMW 刷新登录，再同步授权，查看 `auth_info` 的实际到期时间。

**无法确认唯一车辆。**

在 My BMW 确认当前车辆，再在 `setup_new` 参数里填写完整 `vin`。配置冲突时应先核对官方车辆选择。

**想撤下组件。**

先运行 `hidden_remove`，等待后用 `hidden_inspect`、`hidden_status` 核对专用宿主无实例；再运行 `updates_off`，删除 BMW 卡片和脚本。不要直接删除系统的小组件注册文件。

# 目录说明

```text
manifest.xml                  背屏布局、展示及按钮
var_config.xml                原生外观编辑配置
widget_info.json              云端安装元数据
source/                       后台和主脚本编辑源文件
scripts/                      构建生成的云端配套脚本
source/appearance.lua          本地外观读取兼容通道
build.py                      生成本地、云端及仓库源码 ZIP
README.md                     项目与使用说明
自定义外观使用说明.md           外观设置及排查
技术交接.md                   维护依据、数据流和验证边界
发布说明.md                   GitHub Release 和云端收录步骤
reference_*/                  离线回归用的历史基线
```

本地发行包的脚本位于 ZIP 根目录，云端发行包的脚本位于 `scripts/`。修改功能后应运行构建重新生成配套包，避免手动混合不同版本的模板和脚本。
